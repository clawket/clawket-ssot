## 누구인가

메인 코딩 에이전트가 일을 **병렬로 나눠 처리하려고 띄우는 보조 실행 주체**다. 사람이 한 프로젝트에서 여러 세션을 동시에 돌리듯, 에이전트도 한 작업 안에서 여러 서브에이전트를 동시에 띄워 여러 태스크를 나란히 진행할 수 있다.

서브에이전트는 독립적으로 일하지만 Clawket의 추적 체계 밖에 있지 않다. 스폰되는 순간 자신이 맡을 태스크에 자동으로 묶이고(바인딩), 일을 끝내면 그 결과가 해당 태스크의 기록으로 남는다. 즉 "누가 이 일을 했는가"가 사람의 개입 없이 자동으로 연결된다.

병렬로 여럿이 동시에 발동하면 충돌 위험이 생기는데, 이는 데몬이 해결한다. 동시에 터지는 시작/종료 훅을 데몬이 **큐로 받아 직렬화**하므로, SQLite 단일 writer 원칙이 유지되고 상태가 꼬이지 않는다.

## 무엇을 하려고 제품을 쓰나

서브에이전트의 목표는 **"배정받은 태스크 하나를 끝까지 수행하고, 증거와 함께 자동으로 닫는 것"**이다. 사람이나 메인 에이전트가 일일이 마감 처리하지 않아도 되도록 라이프사이클이 훅으로 자동화되어 있다.

- **시작 시** — 시작 훅이 서브에이전트를 배정 태스크에 바인딩한다. 동시에 검증 워크플로우에 필요한 점검(시나리오 연결 여부, 에이전트 배치 크기, 동기화 계층 순수성)이 함께 돌아간다.
- **종료 시** — 종료 훅이 작업 결과 요약을 태스크에 덧붙이고, 완료에 필요한 증거(evidence)가 있는지 검사한다. 성공 조건을 만족하면 태스크를 자동으로 done 처리한다.

검증 라운드 같은 특수한 맥락에서는 이 서브에이전트가 정해진 형태(예: 배치당 1개의 QA 추론 서브에이전트)로 스폰되어 시나리오를 코드에 대조하는 근거 산출 작업을 수행하기도 한다.
