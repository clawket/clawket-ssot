## 누구인가

Clawket을 사용하는 환경에서 실제로 코드를 작성·수정하고 명령을 실행하는 자동화 주체다. 구체적으로는 Claude Code 형태의 LLM 코딩 에이전트이며, 사람이 키보드로 타이핑하는 대신 대화 맥락을 받아 파일을 편집하고, 쉘 명령을 돌리고, 하위 작업자(서브에이전트)를 띄운다.

이 에이전트의 가장 큰 특징은 **상태를 스스로 오래 기억하지 못한다**는 점이다. 세션이 새로 시작되면 "내가 어디까지 했더라"에 대한 답을 잃는다. Clawket은 바로 이 약점을 메우기 위한 도구로, 에이전트가 다루는 모든 작업·계획·지식·실행 이력을 로컬에 영구 보존하고, 새 세션이 시작될 때 그 맥락을 다시 주입해 준다.

에이전트는 사람 운영자와 **같은 상태를 공유**한다. 사람은 웹 대시보드로, 에이전트는 명령줄(CLI)과 MCP 도구로 동일한 데이터를 읽고 쓴다. 즉 둘은 서로 다른 창구로 같은 진실을 본다.

기술 수준 측면에서는, 코드 작성·도구 호출·서브에이전트 조율까지 할 수 있는 고숙련 주체지만, 규칙을 강제하지 않으면 절차를 건너뛰거나(예: 계획 없이 바로 코드 변경) 근거 없이 작업을 완료 처리하려는 경향이 있다. 그래서 Clawket은 이 에이전트를 **느슨한 권고가 아니라 훅으로 강제되는 가드레일** 안에서 일하게 만든다.

## 무엇을 하려고 제품을 쓰나

- **컨텍스트 연속성 확보** — 세션이 끊겨도 직전까지의 작업·결정·지식을 다시 불러와 끊김 없이 이어간다. 새 세션 시작 시 활성 작업 요약이 자동으로 주입되고, 필요하면 과거 결정·유사 작업을 의미 검색으로 직접 끌어온다.
- **구조화된 작업 수행** — "프로젝트 등록 → 계획 승인 → 작업 시작 → 작업 완료"라는 정해진 흐름을 따라, 무엇을 왜 하는지가 기록으로 남는 방식으로 일한다. 활성 태스크가 없으면 코드 변경 도구 자체가 막히므로, 항상 "지금 무슨 작업을 하고 있는지"가 명시된 상태에서만 손을 댄다.
- **근거를 남기며 완료** — 작업을 끝낼 때 단순 "완료"가 아니라 무엇으로 그것이 끝났다고 판단했는지(근거)를 함께 남긴다. 완료 처리는 이 근거가 있어야 통과된다.
- **안전한 자동화** — 파괴적 명령(작업 트리를 되돌리는 류)이나 절차 우회는 가드레일에서 막히므로, 자율적으로 오래 돌더라도 사용자가 원치 않는 파괴를 일으키지 않는 선 안에서 움직인다.
