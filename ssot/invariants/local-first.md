## 제약

Clawket이 다루는 모든 데이터는 사용자의 기계 안에서만 만들어지고 보관되고 처리된다. 태스크·플랜·지식 문서·활동 로그 등 모든 상태는 로컬 SQLite 데이터베이스 한 곳에 저장된다. 이 상태를 제공하는 데몬은 외부에서 접근할 수 없는 경로(자기 자신을 가리키는 루프백 주소와, 같은 기계 안에서만 통하는 유닉스 도메인 소켓)에만 귀를 열고, 바깥으로 나가는 네트워크 요청을 스스로 만들지 않는다. 지식 검색에 쓰이는 임베딩(의미 벡터 변환)도 클라우드 API가 아니라 기계 안에서 도는 온디바이스 모델로 처리하므로, 검색을 위해 어떤 문장도 외부 서비스로 보내지 않는다.

즉 "데이터가 기계 밖으로 나가지 않는다"는 것이 권고가 아니라 아키텍처의 기본 형상이다.

## 깨지면 무슨 일이 일어나나

이 제약이 깨지면 — 데몬이 외부 인터페이스에 바인딩하거나, 임베딩이 클라우드 API로 위임되거나, 상태가 원격 저장소로 동기화된다면 — 사용자가 진행 중인 작업·플랜·내부 지식·코드 맥락이 사용자 동의 없이 외부로 노출될 수 있다. 이는 Clawket을 개인 작업 도구로 신뢰할 수 있게 만드는 전제를 무너뜨린다. 로컬 우선이라는 약속이 곧 프라이버시 보장의 토대이므로, 이 불변식 위반은 곧 신뢰 위반이다.

## 코드에서 어떻게 강제되나

데몬은 바인딩 주소가 기본적으로 자기 자신을 가리키는 루프백으로 설정되어 있고, 별도의 유닉스 도메인 소켓 파일을 통해서도 수신한다. 이 소켓은 같은 사용자만 접근할 수 있도록 권한이 제한된다. 상태 저장은 로컬 파일 시스템의 단일 SQLite 데이터베이스로 고정되어 있으며, 임베딩 처리는 데몬 프로세스 안에서 온디바이스 모델로 수행되어 외부 호출 경로를 거치지 않는다. 외부로 향하는 유일한 네트워크 경로는 바이너리 자체를 GitHub Releases에서 내려받아 설치·갱신할 때뿐이며, 이는 사용자 데이터 전송이 아니라 프로그램 배포 채널이다.
