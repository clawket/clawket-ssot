## 제약

사이클은 타임박스된 반복(스프린트)이며, 항상 하나의 유닛에 소속된다. 사이클을 만들 때 어느 유닛에 속하는지 반드시 지정해야 한다. 같은 유닛 안에서 사이클은 직렬로만 진행된다 — 한 유닛에 활성 상태인 사이클은 최대 하나다. 새 사이클을 시작하려면 같은 유닛의 기존 활성 사이클을 먼저 끝내야 한다.

사이클은 계획(planning)→활성(active)→완료(completed)의 흐름을 가지며, 한 번 완료된 사이클은 되살릴 수 없다. 다시 작업이 필요하면 완료된 사이클을 재가동하는 대신 새 사이클을 만든다.

## 깨지면 무슨 일이 일어나나

한 유닛에 활성 사이클이 둘 이상 공존하면, 같은 작업 묶음 안에서 어느 반복이 "지금 돌고 있는 스프린트"인지 모호해지고 태스크 일정이 두 사이클로 갈라진다. 완료된 사이클을 되살릴 수 있게 되면, 이미 종결 처리된 작업 묶음에 새 변경이 섞여 들어와 사이클이 "확정된 시점의 스냅샷"이라는 의미를 잃는다. 유닛을 지정하지 않은 떠도는 사이클이 생기면 작업 계층(플랜→유닛→사이클)이 끊긴다.

## 코드에서 어떻게 강제되나

CLI 명령 정의 헤더에 이 규칙이 v3.0 불변식으로 선언되어 있고(사이클은 유닛에 속하며 유닛당 활성 하나, 완료 사이클 재시작 불가), 실제 강제는 데몬의 사이클 저장소 로직에서 이뤄진다(`daemon/src/repo/cycles.rs`).

사이클을 활성으로 바꾸려 할 때, 같은 유닛에 이미 활성 사이클이 있으면 거부한다(UNIT_HAS_ACTIVE_CYCLE — 같은 유닛 사이클은 직렬이라는 PDD 규칙). 이미 완료된 사이클을 완료 외 상태로 되돌리려는 시도는 "완료된 사이클은 재시작 불가, 새로 만들라"는 메시지와 함께 막는다. 사이클을 완료로 보낼 때는 끝나지 않은(todo 잔여) 작업이 없는지 확인하는 잔여 게이트를 거친다.
