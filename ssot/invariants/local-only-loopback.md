## 제약

화면(데스크탑 앱·웹 대시보드)은 외부 서버가 아니라, 사용자의 같은 컴퓨터 안에서 도는 데몬에만 붙는다. 기본 연결 대상은 그 기기 자신만 가리키는 루프백 주소이고 기본 포트가 정해져 있다(개발 환경에서는 포트 충돌 시 다음 번호로 밀려날 수 있어 환경 변수로 재정의할 수 있다). 이것은 모든 데이터가 로컬에 머물고 외부로 나가지 않는다는 Clawket의 로컬 우선 성격과 같은 선상에 있으며, 현재 버전(v3)은 이 로컬 전용 가정 위에서 동작한다.

데몬은 연결 요청에 인증을 요구한다. 일반 요청은 전용 토큰을 헤더에 실어 인증한다. 그런데 실시간 이벤트 스트림 연결은 브라우저 표준 방식상 커스텀 헤더를 붙일 수 없다. 그래서 데몬은 토큰 헤더만 고집하지 않고, 한 번 인증된 뒤 따라붙는 세션 쿠키도 인증 수단으로 받아들인다 — 이벤트 연결은 자격 증명(쿠키)을 함께 보내는 방식으로 인증된다.

## 깨지면 무슨 일이 일어나나

화면이 임의의 원격 주소에 붙도록 열리면, 로컬에만 머물러야 할 작업 데이터가 외부로 흘러갈 통로가 생겨 로컬 우선·프라이버시 전제가 깨진다. 한편 인증을 토큰 헤더로만 강제하고 쿠키 경로를 막으면, 헤더를 실을 수 없는 실시간 이벤트 연결이 인증을 통과하지 못해 화면이 변경 사항을 실시간으로 받지 못한다. 그러면 사용자는 다른 곳에서 일어난 변경을 보지 못하고 수동 새로고침에 의존하게 되어 실시간성이 사라진다. "로컬 루프백 전용 + 토큰·쿠키 병행 인증"이라는 조합이 둘 다 성립해야 안전성과 실시간성이 함께 보존된다.

## 코드에서 어떻게 강제되나

데스크탑 데몬 클라이언트는 기본 연결 대상을 루프백 주소·기본 포트로 두고, 개발 시 환경 변수로 재정의할 수 있음을 명시한다. 또 데몬의 TCP 연결이 토큰 헤더 또는 세션 쿠키 중 하나를 요구하며, 웹뷰가 캐시를 직접 읽을 수 없어 토큰을 별도 경로로 받아 헤더로 제시한다고 기록한다(`desktop/apps/desktop/src/data/api.ts`). 실시간 구독 훅은 이벤트 연결이 커스텀 헤더를 설정할 수 없기에 데몬이 세션 쿠키도 허용하며, v3에서는 화면이 루프백 위에서 로컬 전용으로 동작한다는 점을 명시하고 자격 증명을 동반해 연결한다(`desktop/apps/desktop/src/data/hooks/useEvents.ts`). 이 제약은 데몬의 바인딩·인증 정책과 화면의 연결 방식을 함께 묶으므로 시스템 경계를 가로지른다.
