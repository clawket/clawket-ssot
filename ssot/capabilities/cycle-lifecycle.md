## 사용자가 할 수 있는 일
사이클은 유닛 안에서 일을 묶는 타임박스 반복(스프린트)이다. 이 기능으로 사람·에이전트는 사이클을 만들고, 제목·목표를 다듬고, 활성화해 시작하고, 일이 끝나면 완료로 닫는다. 사이클을 만들 때는 반드시 어느 유닛에 속하는지를 지정해야 한다 — 유닛 없는 사이클은 만들 수 없으며, 존재하지 않는 유닛을 지정하면 거부된다. 활성화는 단순 상태 변경이 아니라 사이클의 시작 시각을 찍는 행위라서, 계획 단계 사이클을 시작하려면 일반 수정이 아니라 전용 활성화 경로를 거쳐야 한다. 더해, 사이클에 묶인 태스크를 한 번에 나열하고, 상태별(todo/진행중/완료/차단/취소) 집계를 보고, 같은 유닛의 다른 사이클과 시나리오별 통과/결함 차이를 비교할 수 있다.

## 행위
- 사이클 목록 조회: 프로젝트·유닛·상태로 걸러 나열한다.
- 사이클 생성: 프로젝트·유닛·제목이 필수이며 목표·정렬 순서는 선택이다. 유닛이 비어 있으면 "유닛 필수" 오류로, 지정한 유닛이 없으면 "유닛 없음" 오류로 거부한다.
- 단건 조회·수정·삭제: 사이클 하나를 보고, 제목·목표·상태를 고치고, 지운다.
- 활성화: 계획 단계 사이클을 활성으로 올리며 시작 시각을 기록한다. 계획→활성 전환은 일반 수정으로는 막혀 있고 반드시 이 활성화 경로를 거쳐야 한다.
- 완료: 사이클을 닫는다.
- 태스크 목록 조회: 이 사이클에 배정된 태스크를 모두 돌려준다.
- 카운트 조회: 사이클 내 태스크를 상태별로 집계해 한 번에 돌려준다.
- diff 조회: 이 사이클과 비교 대상 사이클의 시나리오별 차이(고쳐짐·깨짐·유지·신규·삭제)를 계산한다. 비교 대상을 지정하지 않으면 같은 유닛에서 이 사이클 직전에 생성된 사이클을 자동으로 잡는다.

## 시스템 흐름
요청은 데몬의 사이클 HTTP 라우트로 들어온다. 생성 시 데몬은 유닛 지정 여부와 유닛 존재를 먼저 검사하고 통과해야 사이클을 만든다. 활성화·완료 시에는 상태가 실제로 바뀌면 변경 이벤트를 발행해 웹 대시보드 등 구독자에게 알린다. 계획→활성 직접 변경 시도는 활성화 경로로 가도록 막아, 시작 시각이 누락되지 않게 한다. diff는 두 사이클 각각의 시나리오 태스크를 모아 짝지어 차이를 계산하며, 비교 대상이 비어 있으면 같은 유닛의 직전 사이클을 기본값으로 채운다.

## 어디에 구현되어 있나
데몬의 사이클 라우트 계층(`daemon/src/routes/cycles.rs`)이 목록·생성(유닛 필수·존재 검사 포함)·조회·수정·삭제, 활성화·완료와 이벤트 발행, 사이클 내 태스크 목록과 상태별 카운트 집계, 그리고 사이클 간 시나리오 diff의 HTTP 표면과 판정 로직을 담는다. 사람·에이전트는 CLI(사이클 명령)와 웹 대시보드를 통해 호출한다.
