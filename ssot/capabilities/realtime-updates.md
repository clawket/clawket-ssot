## 사용자가 할 수 있는 일

웹 대시보드를 보는 사람은 화면을 직접 새로고침하지 않아도, 데몬에서 일어난 변화(태스크 상태 변경, 새 실행 기록 등)가 화면에 자동으로 반영되는 것을 본다. 같은 상태를 LLM 에이전트가 CLI로 바꾸든 다른 창에서 누가 바꾸든, 열려 있는 화면은 곧 최신으로 따라온다.

연결이 정상이 아닐 때도 사용자는 혼란 없이 상황을 안다. 데몬이 응답하지 않으면 화면 상단의 상태 표시가 "정상 아님"으로 바뀌고, 본문은 빈 캔버스 대신 "데몬이 오프라인"임을 설명하는 안내 화면으로 교체된다. 이 안내에는 데몬을 직접 켜는 명령(`clawket daemon start`)과, 한 번 누르면 다시 연결을 시도하는 재연결 버튼이 함께 제공된다. 연결이 끊기거나 다시 살아날 때는 토스트 알림으로도 즉시 알려준다.

또한 데몬은 살아 있지만 한동안 아무 변화도 흘러오지 않으면(스트림이 멈춘 듯한 상태), 화면은 그 "지연(lagging)" 상태를 별도로 구분해 상단 표시에 반영한다. 사용자가 연결이 멀쩡한 줄 알고 오래된 데이터를 신뢰하는 일을 막기 위해서다.

## 행위

- **변경 이벤트 수신·반영**: 데몬의 SSE 스트림을 구독해 들어오는 변경 이벤트를 화면 상태에 점진적으로 합쳐, 바뀐 부분만 다시 그린다.
- **실행 기록(run) 실시간 추적**: 실행이 생성·갱신될 때 그에 묶인 화면(타임라인·활동 등)을 폴링 없이 새로 그린다. 특정 태스크에 한정해 구독할 수도 있다.
- **데몬 생존 확인**: 일정 주기로 데몬 헬스를 핑해 연결 여부를 판단하고, 상태가 바뀌는 순간에만 사용자에게 알린다.
- **재연결**: 사용자가 재연결 버튼을 누르면 헬스 핑을 즉시 다시 하고 SSE 스트림도 새로 연다. 데몬이 다시 살아나는 것을 감지하면 자동으로도 스트림을 다시 잇는다.
- **끊김 안내**: 데몬이 응답하지 않는 동안 본문을 설명형 빈 화면으로 바꾸고 재연결 행동을 유도한다.

## 시스템 흐름

화면이 열리면 헬스 핑이 주기적으로 데몬 생존을 확인하고, 동시에 변경 이벤트 스트림을 연결한다. 스트림이 열리면 "연결됨"으로 표시되고, 이후 들어오는 각 변경 이벤트는 화면 상태에 합쳐져 해당 영역만 다시 렌더링된다. 스트림이 끊기면 브라우저가 자동 재연결을 시도하며, 화면은 그 사이 상태를 "재연결 중" 또는 "끊김"으로 구분해 보여준다.

데몬 자체가 응답하지 않게 되면(헬스 핑 실패) 본문이 안내 화면으로 교체되고, 사용자가 재연결을 누르면 헬스 확인과 스트림 재연결이 한꺼번에 다시 시작된다. 데몬이 다시 살아나면 자동으로 스트림이 복구된다. 끊김 동안 받지 못한 변경은, 재연결 시 마지막으로 받은 이벤트 지점을 기준으로 데몬의 리플레이로 메워 빈틈을 줄인다.

상단 상태 표시는 단순히 "데몬에 닿는지"만이 아니라 "스트림이 연결되어 있고, 최근에 신호가 흘렀는지"까지 종합해 정상/지연/끊김을 가른다.

## 어디에 구현되어 있나

웹 대시보드의 최상위 셸(`web/src/App.tsx`)이 전체 흐름을 조율한다 — 변경 이벤트 스트림 구독·점진 반영, 연결 상태 표시, 데몬 오프라인 안내 화면, 재연결 버튼이 여기에 묶여 있다. 데몬 생존 확인과 상태 변화 알림은 `web/src/hooks/useDaemonHealth.ts`가, 실행 기록의 실시간 구독(연결 여부·재연결 횟수 포함)은 `web/src/hooks/useRunEvents.ts`가 담당한다. 이 화면들이 의존하는 변경 스트림과 헬스 응답은 데몬이 제공한다.
