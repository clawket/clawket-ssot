## 사용자가 할 수 있는 일

LLM 에이전트나 사람 운영자는 태스크가 실제로 돌아간 사실을 기록으로 남기고 되돌아볼 수 있다. 실행을 시작·종료로 표시하면 어떤 에이전트가 언제 실행해 어떤 결과(성공·실패 등)와 메모를 남겼는지 보존된다. 또 특정 태스크의 실행 목록과 개별 실행 상세를 조회할 수 있다.

여기에 더해 "그때 그 엔티티는 어떤 상태였나"를 사후에 복원할 수 있다. 원하는 시점을 지정하면 그 시점까지의 변경 이력을 차례로 적용해 당시의 필드 상태(스냅샷)를 재구성해 준다. 시점을 비우면 전체 이력을 끝까지 접어 현재까지의 누적 상태를 보여준다.

## 행위

- 실행 생성: 태스크에 새 실행을 건다. 시작 상태("started")로 바로 시작하거나, 프롬프트·스냅샷만 먼저 받고 아직 태스크를 점유하지 않는 대기 상태("pending")로 둘 수 있다. 이미 끝나지 않은 실행이 있으면 새 실행 생성을 막는다(이미 열린 실행 존재 시 거절).
- 봉투 동결: 실행을 만들 때 호출자가 봉투 스냅샷을 직접 주면 그것을, 주지 않고 태스크에 활성 봉투가 있으면 그 시점의 봉투 체인을 풀어 동결한 결과를 함께 보존한다.
- 실행 시작 전환: 대기 상태의 실행을 시작 상태로 넘긴다.
- 실행 종료: 실행에 결과 값과 메모를 달아 종료로 표시한다.
- 조회: 태스크·세션·프로젝트 기준으로 실행 목록을 거르거나, 단건 상세를 본다.
- 엔티티 리플레이: 지정 시점까지의 변경 이력을 시간순으로 적용해 그 시점의 상태 스냅샷, 되감아간 마지막 시각, 적용한 이력 건수를 돌려준다. 이력 중 삭제 시점을 만나면 그 지점에서 스냅샷을 비운다.

## 시스템 흐름

호출자가 실행 생성을 요청하면 데몬은 먼저 대상 태스크가 있는지 확인하고, 이미 열린 실행이 있는지 검사한다. 통과하면 상태(대기/시작)와 봉투 스냅샷을 정해 실행을 만들고, 실시간 이벤트로 "실행 생성"을 알린다. 시작·종료 전환도 각각 갱신 이벤트를 내보내 웹 대시보드·관찰 도구가 즉시 반영하게 한다.

리플레이는 저장된 감사 이력을 근거로 한다. 대상 엔티티의 변경 행을 지정 시점 이하로 골라 시간순으로 정렬하고, 각 행의 새 값을 차례로 덮어쓰며 당시 상태를 누적 재구성한다. 데몬은 이 과정을 외부 의존 없이 로컬에서 수행한다.

## 어디에 구현되어 있나

- `daemon/src/routes/runs.rs`: 실행의 생성·시작·종료·목록·상세 처리, 봉투 스냅샷 동결, 그리고 엔티티의 시점 기반 리플레이까지 한 곳에서 다룬다.
