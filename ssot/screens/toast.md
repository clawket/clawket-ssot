## 화면 목적

토스트는 독립된 페이지가 아니라 데스크탑 앱 전체에 항상 떠 있는 알림 영역이다. 화면 오른쪽 아래 모서리에 짧은 메시지를 쌓아 보여주고, 일정 시간이 지나면 스스로 사라진다. 사용자가 작업하던 화면(보드·백로그·타임라인·위키 등)을 떠나거나 막지 않으면서, "방금 무슨 일이 일어났다"를 알려주는 것이 목적이다.

가장 대표적인 쓰임은 로컬 데몬과의 연결 상태 변화다. 데몬이 끊기면 "연결이 끊겼습니다. 재연결을 시도합니다" 류의 메시지가 뜨고, 다시 붙으면 "재연결되었습니다" 메시지가 뜬다. 그 밖에도 앱 안의 어떤 동작이든 성공·실패·경고·정보를 사용자에게 가볍게 통지하고 싶을 때 같은 영역을 공용으로 쓴다.

## UI 요소 / 입력 필드

토스트는 사용자가 값을 입력하는 화면이 아니라 읽고 닫는 화면이다. 한 건의 토스트는 다음을 보여준다.

- 심각도 아이콘: 정보·성공·경고·오류 네 종류로 구분되며, 각각 색과 기호(정보 ℹ, 성공 ✓, 경고 ⚠, 오류 ✕)가 다르다. 사용자는 색·아이콘만으로 메시지의 성격을 즉시 구분할 수 있다.
- 메시지 본문: 무슨 일이 일어났는지를 한 줄 안팎의 자연어로 보여준다.
- 반복 횟수 표시: 똑같은 메시지가 짧은 사이에 여러 번 발생하면 토스트를 여러 개 쌓지 않고 하나로 합치며, 옆에 "×N" 형태로 몇 번 반복됐는지를 붙인다.
- 닫기 버튼: 사용자가 직접 토스트를 즉시 없앨 수 있다.

심각도별 머무는 시간이 다르다. 일반 정보·성공·경고는 일정 시간(기본 수 초) 뒤 자동으로 사라지고, 오류는 사용자가 직접 닫기 전까지 화면에 계속 남는다(놓치면 안 되는 실패는 사라지지 않게 한 의도).

## 표시 데이터 / 호출 API

토스트가 보여주는 정보는 백엔드에서 따로 조회해 오는 데이터가 아니라, 앱 내부에서 발생한 사건을 그대로 옮긴 것이다. 토스트 영역 자체는 서버 API를 직접 호출하지 않는다 — 다른 화면·로직이 어떤 사건(예: 데몬 헬스 체크 결과 변화, 어떤 동작의 성공/실패)을 감지하면 앱 내부의 알림 통로로 메시지를 흘려보내고, 토스트 영역은 그것을 구독해 화면에 띄우는 역할만 한다.

대표 데이터 출처는 데몬 연결 상태다. 앱은 로컬 데몬의 헬스 상태를 주기적으로 확인하다가, 끊김→연결 또는 연결→끊김으로 바뀌는 순간 그 변화를 토스트로 알린다.

## 상태 / 엣지케이스

- 알림 없음: 띄울 토스트가 하나도 없으면 토스트 영역은 화면에 아무것도 그리지 않는다.
- 동일 메시지 중복: 같은 내용의 알림이 짧은 간격으로 반복되면 새 토스트를 쌓는 대신 기존 토스트의 반복 횟수만 늘리고 머무는 시간을 갱신한다. 화면이 같은 메시지로 도배되지 않도록 막는다.
- 자동 소멸 vs 고정: 정보·성공·경고는 시간이 지나면 부드럽게 사라지지만, 오류는 자동으로 사라지지 않고 사용자가 닫을 때까지 남는다.
- 수동 닫기: 자동 소멸을 기다리지 않고 사용자가 닫기 버튼으로 즉시 제거할 수 있으며, 사라질 때 짧은 전환 효과를 거쳐 제거된다.
- 접근성: 알림 영역은 화면 낭독기에 정중하게(polite) 읽히도록 표시되어, 작업 흐름을 끊지 않으면서도 보조기술 사용자에게 상태 변화를 전달한다.
