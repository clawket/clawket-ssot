## 화면 목적
로컬 데몬이 떠 있는 상태에서 사람 운영자가 브라우저로 데몬의 루트 주소에 접속하면 만나는 화면이다. 이 화면 자체는 "껍데기 문서" 한 장이고, 그 안에 담긴 React 대시보드가 로드되면서 Summary·Board·Backlog·Timeline·Wiki 같은 실제 작업 뷰로 이어진다. 즉 사람이 Clawket의 상태를 눈으로 보기 위해 가장 먼저 도달하는 입구다.

## UI 요소 / 입력 필드
이 진입 화면 자체에는 사용자가 직접 입력하는 필드가 없다. 두 갈래로 갈린다.

- 대시보드가 정상적으로 빌드되어 있으면: 빌드된 React 대시보드 문서를 그대로 내려주고, 이후의 화면·입력은 모두 대시보드 SPA가 담당한다.
- 대시보드가 아직 빌드되지 않았으면: "Clawket dashboard not built"라는 안내 페이지를 보여준다. 이 안내문은 데몬은 살아 있지만 대시보드 산출물(index.html)을 찾지 못했다는 사실과, 저장소에서 웹 대시보드를 빌드하는 방법(웹 디렉터리로 들어가 설치·빌드)을 알려준다. 또한 대시보드 없이도 작업관리 기능(프로젝트·플랜·유닛·태스크·사이클 등)에 직접 접근할 수 있는 경로가 있음을 함께 안내한다.

## 표시 데이터 / 호출 API
이 진입 화면을 응답할 때 데몬은 두 가지를 함께 처리한다.

- 캐시 정책: 이 진입 문서는 일부러 캐시하지 않는다(no-store). 매번 새로 받아오게 해서, 아래의 세션 토큰이 오래된 값으로 굳지 않도록 한다.
- 세션 토큰 부트스트랩: 응답에 브라우저 전용 세션 쿠키를 함께 심는다. 이 쿠키는 CLI가 토큰 파일에서 읽는 것과 동일한 인증 토큰을 담아, 이후 SPA가 데몬 API를 호출할 때 자동으로 인증되도록 한다. 쿠키는 자바스크립트가 직접 읽지 못하도록(HttpOnly) 보호되고 동일 사이트 요청에만 전송되도록(SameSite=Strict) 제한되어, 스크립트 탈취나 교차 사이트 위조 요청 위험을 줄인다. 토큰 자체가 비어 있으면 쿠키를 심지 않는다.

이 진입 화면 자체는 별도의 작업관리 API를 호출하지 않는다. 데이터 조회·변경은 이 화면이 로드한 대시보드 SPA가 데몬 API·이벤트 스트림에 붙어 수행한다.

## 상태 / 엣지케이스
- 정상 상태: 대시보드 산출물 위치가 잡혀 있고 진입 문서를 읽을 수 있으면 그 문서를 응답한다.
- 미빌드/누락 상태: 대시보드 위치가 설정돼 있지 않거나 진입 문서를 읽지 못하면 "서비스 일시 불가"에 해당하는 응답과 함께 빌드 안내 페이지를 보여준다. 둘 다 같은 안내 화면으로 수렴한다.
- 인증 미설정: 데몬에 토큰이 비어 있는 경우 세션 쿠키 없이 진입 문서만 응답한다.
