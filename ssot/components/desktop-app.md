## 책임

데스크탑 앱은 웹 대시보드가 보여주는 것과 동일한 단일 페이지 화면을, 브라우저가 아닌 독립된 데스크탑 창에서 띄우도록 의도된 클라이언트다. 사람 운영자가 작업 상태(요약·보드·백로그·타임라인·위키)를 브라우저 탭이 아니라 별도의 앱 창에서 보고 관리하게 하는 것이 목적이다. 화면 자체는 웹과 같으므로, 데스크탑 앱은 새로운 기능을 더하기보다 "같은 대시보드를 데스크탑 형태로 감싸는" 껍데기 역할을 맡는다.

중요한 사실은 이 컴포넌트가 현재 출시 전 상태라는 점이다. 데스크탑 앱은 별도 저장소와 별도 릴리스 채널을 가지도록 배선되어 있지만, 첫 릴리스가 아직 만들어지지 않았다. 플러그인이 각 구성요소의 버전을 적어 두는 핀 목록에서 데스크탑 항목만 값이 비어 있고(나머지 CLI·데몬·웹은 버전이 박혀 있다), 이 빈 값이 곧 "아직 없음"을 뜻하는 약속된 표식이다.

## 경계와 의존

데스크탑 앱은 다음에 의존하도록 설계되어 있다.

- 데몬: 데스크탑 창 안의 대시보드는 로컬 데몬의 HTTP API와 실시간 이벤트에 붙어 같은 데이터를 읽고 쓴다. 웹 대시보드와 동일한 데이터 소스를 공유한다.
- 웹 대시보드: 데스크탑 앱은 웹과 같은 SPA를 렌더링하는 구조이므로, 화면·동작 면에서 웹 대시보드 구현을 그대로 재사용하는 관계다.

데스크탑 앱은 외부에 API를 제공하지 않으며, 자신이 직접 노출하는 백엔드 엔드포인트도 없다. 데이터 접근은 어디까지나 데몬을 통해 이뤄진다. 설치 산출물 형태는 실행 가능한 단일 바이너리가 아니라 운영체제별 설치 프로그램(맥의 .dmg, 윈도의 .msi, 리눅스의 .AppImage)이며, 플러그인은 이 설치 프로그램을 사용자가 직접 실행하도록 받아만 둘 뿐 자동으로 설치를 진행하지 않는다.

## 통신 패턴

설치 측면의 통신은 GitHub Releases 연동을 통해 이뤄진다. 데스크탑 버전 핀이 실제 태그 값으로 채워지면, 설치 절차가 데스크탑 전용 저장소의 해당 릴리스에서 운영체제에 맞는 설치 프로그램을 내려받아 플러그인 디렉터리 아래에 staging 해 두고, 사용자가 직접 그것을 실행하도록 안내한다. 다운로드가 실패해도 치명적 오류로 다루지 않고, 수동으로 내려받는 방법을 안내하는 비치명적 처리로 넘어간다.

핀이 비어 있는 현재 상태에서는 이 통신 자체가 일어나지 않는다. 빈 핀은 설치 절차에서 명시적 무동작으로 처리되어, 데스크탑 항목은 다운로드도 검증도 건너뛴 채 "준비 완료"로 간주된다. 따라서 데스크탑 앱이 출시되기 전까지는 설치 게이트가 이 컴포넌트 때문에 막히는 일이 없다.

실행 시 통신 패턴(데몬과의 HTTP·이벤트 교신)은 웹 대시보드와 같으나, 앱이 아직 배포되지 않으므로 런타임 통신은 미출시 상태에서는 발생하지 않는다.

## 하위 서브패키지 (책임 단위)

데스크탑 앱의 소스는 이 플러그인 셸 저장소가 아니라 별도의 데스크탑 전용 저장소에 위치한다. 플러그인 셸 안에는 버전 핀과 설치/건너뛰기 로직만 존재하며, 앱 본체의 구성(Tauri 셸과 SPA 패키지)은 외부 저장소의 책임이다. 따라서 본 노드는 플러그인 셸 관점에서 본 "배선과 미출시 상태"를 다루며, 앱 내부 구조는 범위 밖이다.
