## 책임

데이터 공급자는 데스크탑 화면 전체가 같은 데이터를 보게 하는 한 곳의 진실 계층이다. 앱이 켜지면 활성 프로젝트를 정하고, 그 프로젝트에 속한 플랜·유닛·사이클·태스크·타임라인·지식·위키 파일·실행 기록을 한꺼번에 병렬로 불러온다. 이 초기 적재 중 하나라도 실패하면 화면을 어중간하게 절반만 채우지 않고 한 번에 하나의 일관된 오류를 보여 준다. 다만 디스크 위키 파일과 실행 기록은 없거나 접근이 막혀도 나머지 화면이 뜨도록 부드럽게 빈 결과로 넘어간다.

활성 프로젝트는 이전에 고른 것을 기억해 다시 쓰되, 그 프로젝트가 사라졌으면 기본값·활성화된 첫 프로젝트 순으로 합리적으로 골라 준다. 사용자가 프로젝트를 바꾸면 선택을 저장하고 데이터를 다시 불러온다.

데몬에서 무언가 바뀌면 실시간 이벤트로 알림이 오는데(태스크·플랜·유닛·사이클·지식·코멘트의 생성·수정·삭제 등), 이때 공급자는 바뀐 종류의 목록만 다시 받아 와 갱신한다. 이벤트 자체에는 식별자만 담겨 오므로 통째로 다시 받는 편이 더 정확하고 싸다는 판단에서다. 삭제 이벤트는 네트워크를 타지 않고 화면 상태에서 곧장 그 항목을 지운다. 태스크가 시작·완료·취소되면 실행 기록도 함께 새로 받아 타임라인이 최신을 비추게 한다. 지식이 바뀌면 디스크 위키 파일 목록도 같이 갱신한다.

모든 쓰기 동작(프로젝트·플랜·유닛·사이클·태스크의 생성·수정·삭제, 플랜 승인·완료, 사이클 활성화·완료, 하위 태스크 생성, 분해 제안 요청, 코멘트·질문·실행 기록 조회 등)은 공급자가 데몬으로 라우팅한다. 라우팅 과정에서 데몬의 규칙도 화면이 자연스럽게 지키도록 감싼다. 예를 들어 태스크를 완료 처리하려면 근거를 함께 넘겨야 하고, 사이클 활성화·완료는 일반 수정이 아닌 전용 경로로 보내며, 삭제는 데몬이 상황에 따라 진짜 삭제하거나 취소 상태로 바꾸는데 화면은 그 차이를 신경 쓰지 않아도 되도록 일관된 모양으로 돌려준다. 삭제·완료 같은 동작은 화면이 즉시 반응하도록 먼저 낙관적으로 반영한 뒤 데몬에서 받은 진실로 다시 맞춘다.

## 경계와 의존

데이터 공급자는 데스크탑 렌더러(`component.renderer`) 안에 사는 상태 계층으로, 화면을 그리지는 않고 화면이 쓸 데이터와 동작 함수를 한 묶음으로 노출한다. 사람 운영자(`persona.human-operator`)의 모든 화면 동작이 결국 이 계층을 거친다.

외부로는 로컬 데몬(`component.daemon`)에 의존한다. 읽기·쓰기 모두 데몬 HTTP API로 가고, 연결 생존은 데몬 헬스(`endpoint.daemon-health`)로 확인하며, 실시간 변경 알림은 데몬 이벤트 스트림(`endpoint.daemon-events`)에서 받는다. 그 이벤트 스트림 구독 자체는 전용 SSE 훅(`component.sse-hook`)에 맡기고, 공급자는 거기서 올라온 이벤트를 받아 어떤 목록을 다시 받을지 결정한다.

## 통신 패턴

읽기는 초기 병렬 페치와 이벤트 기반 부분 재적재 두 갈래로 이뤄진다. 쓰기는 데몬 API 호출 뒤 해당 목록을 다시 받아 화면 상태를 데몬의 진실에 맞춘다. 실시간 변경은 SSE 훅이 받아 공급자의 처리 함수로 전달하고, 공급자는 종류별로 목록을 다시 받거나 삭제를 즉시 반영한다. 상태 갱신은 순수한 리듀서로 처리하고 부수효과는 한 곳의 효과에 모은다.

## 하위 서브패키지 (책임 단위)

- 상태 리듀서: 적재·갱신·삭제·SSE 상태를 순수 함수로 다루는 부분.
- 초기 병렬 페치: 활성 프로젝트를 정하고 그 범위의 데이터를 한꺼번에 불러오는 부분.
- 활성 프로젝트 선택·저장: 기억된 선택을 복원하고 사라진 경우 합리적으로 고르는 부분.
- CRUD 라우팅: 각 엔티티의 생성·수정·삭제·전용 동작을 데몬으로 보내고 결과를 다시 맞추는 부분.
- 이벤트 처리: SSE 훅이 올린 변경을 받아 종류별 재적재·삭제 반영을 거는 부분.
