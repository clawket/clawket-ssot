## 책임

이 컴포넌트는 `clawket doctor` 명령의 실제 동작을 구현하는, CLI 안의 읽기 전용 진단 엔진이다. 환경을 건드려 고치지는 않고, 상태를 들여다보고 사람이 읽을 보고서를 항목별로 펼친다. 각 점검 결과에는 정상·정보·경고·오류 같은 심각도가 붙고, 마지막에 오류가 하나라도 있으면 명령 전체를 실패로 끝낸다(자동화·훅이 결과를 신뢰할 수 있도록).

점검하는 영역은 대략 다음과 같다.

- **데몬 건강**: 데몬이 소켓으로 응답하는지, 가동 시간·버전 등. 데몬이 안 떠 있으면 "시작해 보라"는 안내를 붙이되, 사용자가 의도적으로 격리 환경(소켓 경로를 직접 지정)을 쓰는 경우는 오류가 아니라 정보로 낮춰 처리한다.
- **데이터 경로 분리 불변식**: 데이터·캐시·설정·상태·DB 경로가 Claude Code 플러그인 디렉터리 아래로 겹쳐 들어가지 않았는지 검사한다. 겹치면 플러그인 재설치 시 데이터가 지워질 수 있으므로 오류로 강하게 경고하고 해결 방법을 안내한다.
- **데이터 손실 위험 패널**: 위 경로 겹침, 데이터 폴더가 다른 사용자도 쓸 수 있게 열려 있는지, 옛 버전 잔재 경로, 직전 실행 대비 작업 수가 급감했는지, DB 파일 신선도(백업 없이 갓 생성됐는지) 등을 한 묶음으로 점검한다.
- **데이터베이스·감사 로그**: DB 파일 존재·크기와 주요 엔티티 개수, 감사 로그의 최근 항목과 변조 탐지용 해시 사슬의 무결성.
- **바이너리·플러그인 설치**: 데몬 실행 파일 위치, 현재 CLI 바이너리, 플러그인 디렉터리와 설치 마커 버전이 현재 바이너리 버전과 어긋나는지(어긋나면 재설치 안내).
- **훅·MCP·스킬**: 훅 핸들러 파일들의 존재와 이벤트별 마지막 발화 시각, MCP가 노출하는 읽기 전용 도구 목록, 스킬 점검.
- **다국어·티어**: 로케일 해석 체인과 번역 파일 커버리지, 기본 티어 정책, 작업들의 티어 분포와 에스컬레이션율(상위 티어로 올라간 비율) 점검.

## 경계와 의존

이 컴포넌트는 CLI 바이너리(`component.cli`)의 일부로 컴파일되는 내부 모듈이다. 데몬 상태·엔티티 수·감사 로그 같은 정보를 얻으려면 데몬에 물어봐야 하므로 데몬 통신 계층(`component.daemon-client`)을 통해 헬스(`endpoint.daemon-health`)와 조회 계열 API를 호출한다. 검사할 경로 후보와 경로 겹침 판정 규칙은 경로 해석 컴포넌트(`component.paths`)와 공유한다.

설치 마커·버전 정합성 점검은 GitHub 릴리스 기반 배포(`integration.github-releases`)와 맞물리고, 로케일 해석·번역 커버리지 점검은 다국어 체인(`integration.i18n-locale`)과 맞물린다. 데이터 경로 분리 불변식을 지키는 것은 모든 데이터가 로컬에 안전히 머무는 local-first 동작(`platform.local-first`)을 직접 보호하는 행위다.

## 통신 패턴

데몬과는 읽기 전용 HTTP 조회로만 대화한다(상태를 바꾸지 않는다). 데몬이 응답하지 않는 항목은 실패로 단정하지 않고 "데몬 비가용 — 이 항목은 생략"처럼 정보 수준으로 표시해, 오프라인 진단에서도 보고서가 끝까지 출력되게 한다. 결과는 사람이 읽는 텍스트 보고서 또는 기계가 읽는 형식으로 낼 수 있다.

## 하위 서브패키지 (책임 단위)

- **진단 실행·보고**: 항목별 점검을 순서대로 돌리고 심각도를 집계해 보고서를 펼치며 최종 종료 코드를 정한다.
- **판정 규칙 모음**: 활동 로그 보유 예산, DB 신선도, 작업 수 급감, 권한 개방 여부 같은 개별 판정을 순수 규칙으로 분리해 둔 부분.
