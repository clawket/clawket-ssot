## 책임

API 클라이언트는 웹 대시보드와 데몬 사이의 단일 통로다. 화면 컴포넌트들이 데몬의 REST 표면을 직접 만지지 않고 이 함수 모음을 통과하게 함으로써, 인증 부착·에러 해석·요청 직렬화 같은 공통 규칙을 한 곳에 모은다. 프로젝트·플랜·유닛·사이클·태스크·실행·질문·코멘트·실행 봉투·태스크 트리·분해 등 데몬이 노출하는 자원마다 대응하는 함수를 둔다.

요청은 GET·POST·PATCH·DELETE 네 가지 동사로 추상화하고, 응답이 없는 성공(204)은 빈 값으로, 본문이 있는 성공은 JSON으로 풀어 돌려준다. 쿼리 파라미터는 정의되지 않은 값을 걸러 안전하게 직렬화한다.

## 경계와 의존

이 컴포넌트는 데몬 컴포넌트에만 의존한다. 자체 상태를 보관하지 않으며, 호출 대상 기준 출처(origin)는 환경에 따라 달라진다. 운영 시점에는 데몬이 웹 번들을 같은 출처로 서빙하므로 상대 경로면 충분하고, 개발 모드에서는 Vite 개발 서버 포트와 데몬 포트가 달라 일부 경로(특히 SSE)는 데몬 출처로 직접 붙는다. 이 출처 결정은 빌드 타임에 주입되는 데몬 URL 상수를 읽는 별도 모듈이 담당한다.

## 통신 패턴

모든 요청은 자격 증명을 포함(credentials: include)해 보낸다. 데몬은 웹 페이지 응답에 세션 쿠키를 심어 주는데, 이 쿠키는 CLI가 토큰 파일에서 읽는 것과 동일한 토큰을 담고 있어 브라우저의 기본 인증 채널이 된다. 브라우저는 토큰 파일을 직접 읽을 수 없기 때문이다. 동시에 토큰 헤더(X-Clawket-Token)를 보조 채널로 함께 붙인다. 이 헤더 값은 사용자가 한 번 입력해 로컬 스토리지에 저장한 토큰에서 나오며, 쿠키가 흐르지 않는 개발용 교차 포트 상황의 대비책이다. 토큰은 로컬 스토리지를 떠나지 않는다(외부 전송 없음).

데몬이 오류를 돌려주면 클라이언트는 이를 단일 에러 형태로 정규화한다. 데몬이 본문에 실어 보낸 사람이 읽을 수 있는 오류 메시지와 코드가 있으면 그것을 우선 채택하고, 없으면 HTTP 상태로 메시지를 합성한다. 덕분에 화면 레이어는 데몬 오류를 일관된 모양으로 다룰 수 있다.

검색 호출(태스크·지식의 키워드/의미/하이브리드 검색)도 이 클라이언트를 거쳐 데몬의 검색 표면으로 흐른다.

## 하위 서브패키지 (책임 단위)

- **요청 코어**: GET/POST/PATCH/DELETE 래퍼와 에러 정규화, 쿼리 직렬화를 담는 중심 모듈.
- **인증 모듈(auth)**: 토큰을 로컬 스토리지에서 읽고 쓰며 인증 헤더 조각을 만든다.
- **데몬 URL 모듈(daemonUrl)**: 환경별 데몬 출처를 결정해, 프록시를 거치면 안 되는 경로에 절대 URL을 만들어 준다.
