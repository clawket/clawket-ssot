## 책임

앱 셸은 웹 대시보드에서 "지금 무엇을 보고 있는가"를 결정하는 두뇌다. 두 가지를 동시에 책임진다. 하나는 화면을 담는 골격(레이아웃)이고, 다른 하나는 그 골격 안에 무엇을 채울지 결정하는 라우팅·상태 조율이다.

레이아웃 골격은 순수한 배치 컴포넌트의 집합으로, 전체 화면을 좌측 사이드바와 우측 콘텐츠 칼럼으로 나누고, 콘텐츠 칼럼은 상단 바와 본문 영역으로 쌓는다. 이 골격 자체에는 상태가 없고, 누가 어디에 들어가는지만 정한다.

조율 로직은 URL 경로를 해석해 "어느 프로젝트의 어느 뷰(Summary·Board·Backlog·Timeline·Wiki)를 보여줄지, 그리고 태스크·유닛·플랜 중 무엇이 상세 드로어로 열려 있는지"를 도출한다. 경로 형식은 프로젝트 식별자와 뷰 이름, 선택적으로 상세 항목 타입·식별자를 잇는 구조다. 과거 경로(예: 플랜 단독 뷰)는 새 경로로 자동 리다이렉트하는 호환 처리도 여기서 맡는다.

## 경계와 의존

앱 셸은 데몬과 직접 통신하기보다, 상태 조회·변경은 API 클라이언트 하위 컴포넌트에 위임한다. 다만 실시간 갱신만은 셸이 직접 SSE 스트림 연결을 소유한다. 연결 상태(연결 중·연결됨·재연결 중·끊김)와 지연(lagging) 여부를 추적하며, 데몬이 죽으면 본문을 비우는 대신 "데몬 오프라인" 안내와 재연결 버튼을 띄운다.

데몬 생존 확인은 헬스 엔드포인트를 주기적으로 핑하는 별도 훅에 기댄다. 데몬이 다시 살아나면 SSE를 자동 재연결한다.

## 통신 패턴

핵심 패턴은 SSE 기반 점진적 패치다. 데몬은 모든 이벤트 페이로드에 엔티티 타입·변경 타입·이벤트 식별자·타임스탬프를 실어 보내고, 셸의 리듀서는 이를 받아 태스크 단위 변경은 제자리 패치로, 유닛·플랜·사이클·지식·코멘트 변경은 구조적 새로고침 신호로 분기한다. 마지막 이벤트 식별자는 로컬 스토리지에 보존해, 페이지 새로고침이나 재연결 후 데몬 재생(replay) 경로로 빈 구간을 메울 수 있게 한다. 데몬의 30초 주기 keepalive 핑은 데이터 변경은 아니지만 연결 생존 증거로 쓰여, 지연 배지가 깜빡이지 않도록 지연 시계를 갱신한다.

전역 키보드 단축키(명령 팔레트 호출, 도움말 치트시트)와 명령 팔레트의 기본 명령(테마 순환, 뷰 이동, 플랜 열기)도 셸이 묶는다. 상세 드로어는 너비 조절이 가능한 오버레이로 띄우고, 플랜·유닛·태스크 생성 모달과 토스트 컨테이너를 루트에 마운트한다.

## 하위 서브패키지 (책임 단위)

- **AppShell 레이아웃 파트**: 루트·사이드바·콘텐츠·상단바·본문의 순수 배치 컴포넌트 묶음. 내부 상태 없이 전체 뷰포트를 분할한다.
- **App 컨테이너**: URL 파싱, SSE 리듀서, 데몬 헬스·지연 추적, 전역 단축키, 드로어·모달 조율을 담는 최상위 상태 보유 컴포넌트.
