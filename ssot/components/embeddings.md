## 책임

임베딩 엔진은 사람이 읽는 텍스트(태스크 설명, 지식 문서 등)를 컴퓨터가 "의미가 가깝다/멀다"를 계산할 수 있는 숫자 벡터로 바꾸는 부품이다. 이 변환이 있어야 키워드가 정확히 일치하지 않아도 "비슷한 내용"을 찾아내는 의미 검색이 가능해진다 — Clawket 의 로컬 RAG(세션 간 의미 컨텍스트 복원)가 바로 이 벡터 위에서 동작한다.

핵심 책임은 **로컬·다국어 임베딩**이다. 다국어를 지원하는 소형 언어모델을 기기 안에서 직접 돌려, 들어온 텍스트를 일정 길이의 의미 벡터(384차원)로 만든다. 한국어·일본어 등 50여 개 언어를 한 모델로 다루므로, 한국어로 쓴 태스크와 영어로 쓴 지식을 같은 의미 공간에서 비교할 수 있다.

## 경계와 의존

이 엔진은 다른 내부 부품에 직접 의존하지 않는 비교적 독립적인 계산 부품이다. 데몬 프로세스(`component.clawketd`)는 시작 직후, 아직 벡터가 없는 지식·태스크를 찾아 이 엔진으로 채워 넣는 백필 작업을 비동기로 돌리고, 이후 데이터가 새로 생기거나 바뀔 때마다 해당 텍스트의 벡터를 다시 만든다.

이 노드는 배포·역량 관점에서 본 임베딩 엔진(`component.embedding-engine`)을 데몬 내부 구현 관점에서 더 깊게 본 것이다.

## 통신 패턴

가장 중요한 통신 특성은 **외부로 나가지 않는다**는 점이다. 임베딩 계산은 외부 API 호출이 아니라 기기 내부(CPU) 추론으로 이뤄진다. 따라서 태스크·지식 텍스트가 임베딩을 위해 외부 서비스로 전송되는 일이 없다 — Clawket 의 로컬 우선(local-first) 원칙이 검색 영역에서도 유지되는 근거다.

처음 한 번은 모델 파일을 받아 와 메모리에 올려 두고(이후 재사용), 지나치게 긴 텍스트는 모델이 다룰 수 있는 길이로 잘라 처리한다. 비어 있는 텍스트는 벡터를 만들지 않고 건너뛴다.

## 하위 서브패키지 (책임 단위)

- **모델 적재** — 다국어 소형 언어모델과 토크나이저를 한 번 받아 메모리에 상주시킨다.
- **임베딩 변환** — 텍스트를 정규화·절단한 뒤 의미 벡터로 만든다.
