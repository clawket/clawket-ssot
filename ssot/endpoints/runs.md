## 정의
한 태스크가 실제로 어떻게 실행되었는지를 기록한 "실행 기록(run)"을 다루는 API 묶음이다. 사람 운영자가 웹 대시보드에서 특정 태스크의 실행 이력을 펼쳐 보거나, 두 번의 실행을 나란히 비교(RunCompare)하려 할 때 이 API들이 사용된다. 네 가지 동작을 제공한다: 실행 기록 목록 조회, 단건 조회, 새 실행 시작, 진행 중인 실행의 종료.

실무에서 실행 기록은 대부분 Claude Code 훅이 태스크를 시작할 때 자동으로 만들고 종료 시 결과를 채운다. 따라서 이 API의 "시작/종료"는 사람이 직접 부르기보다, 훅이 만들어 둔 기록을 웹에서 읽어 들이는 조회 쪽이 주된 쓰임이다.

## 요청 / 응답
- **목록 조회**: "어느 태스크의", "어느 세션의", "어느 프로젝트의" 실행만 보고 싶은지 좁히는 조건을 함께 보낼 수 있다. 돌려주는 것은 해당 조건에 맞는 실행 기록들의 목록이다. 웹의 실행 비교 화면은 보통 "이 태스크의 모든 실행"으로 좁혀 받아 온다.
- **단건 조회**: 실행 기록 하나의 식별자를 보내면 그 실행 한 건의 전체 내용을 돌려준다.
- **시작**: 어느 태스크에 대한 실행인지(필수)와, 선택적으로 세션·실행 주체(에이전트) 정보를 보내면 새 실행 기록 한 건이 만들어져 돌아온다. 갓 시작된 실행은 아직 끝나지 않은 상태(종료 시각이 비어 있음)다.
- **종료**: 종료할 실행의 식별자와 함께 실행 결과(필수)와 선택적인 노트를 보내면, 종료 처리된 실행 기록이 돌아온다. 노트에는 변경된 파일 목록 같은 부가 정보가 JSON 형태로 담기기도 하며, 웹의 비교 화면은 이 노트를 해석해 두 실행 사이에 바뀐 파일 집합을 시각화한다.

각 실행 기록은 의미상 "어느 태스크의 실행인가", "결과는 무엇인가", "끝났는가(종료 시각 유무)", "부가 노트" 등을 담는다. 끝나지 않은 실행은 결과 대신 "진행 중"으로 표시된다.

## 권한 / 제약
- 로컬 데몬을 호출하는 같은 사용자(사람 운영자 또는 LLM 에이전트)가 사용한다. 데몬은 로컬에만 바인딩되므로 외부 노출이 없다.
- 비교 화면은 한 태스크에 실행 기록이 최소 2건 있어야 동작한다 — 1건 이하이면 "비교하려면 실행이 2건 이상 필요하다"고 안내하고 비교를 건너뛴다.
- 변경된 파일 목록은 노트 안의 JSON을 "최선의 노력(best-effort)"으로 해석한다. 노트가 JSON이 아니면 불투명한 텍스트로 취급하고 파일 목록은 비운다 — 추측하지 않는다.

## provenance
웹 클라이언트의 호출부는 `web/src/api.ts`의 run 관련 함수들(`listRuns`/`getRun`/`startRun`/`finishRun`)이며, 비교 화면에서의 실제 소비는 `web/src/features/runs/RunCompare.tsx`다. 종료는 실행 식별자에 결과·노트를 실어 보내는 별도 경로(`/runs/:id/finish`)를 쓴다. 실제 데이터 저장과 처리는 데몬(component.daemon)이 담당하므로, 응답 형태가 바뀌어도 위 "조회·시작·종료" 의미와 "노트로 변경 파일을 전달한다"는 규약만 유지되면 재구현이 가능하다.
