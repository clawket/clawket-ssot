## 정의
위키 화면이 두 종류의 문서를 함께 보여줄 수 있도록, 데몬이 제공하는 읽기 전용 조회 묶음이다. 하나는 Clawket이 자체 보관하는 지식 항목(작업에 첨부되어 데이터베이스에 쌓인 결정·메모·근거 등)을 계층 트리로 돌려주는 조회이고, 다른 하나는 프로젝트의 실제 작업 폴더 안에 흩어진 마크다운 문서(README, docs 폴더의 설계 문서 등)를 목록과 본문으로 읽어 오는 조회다. 사람 운영자가 웹/데스크탑 대시보드의 위키 탭을 열 때 사용되며, 어느 것도 데이터를 바꾸지 않는다.

이 묶음은 세 갈래로 나뉜다.
- **지식 트리 조회**: 데이터베이스에 저장된 지식 항목을 트리 형태로 반환한다. 특정 루트 항목 아래만 보거나 특정 플랜에 속한 것만 보도록 좁힐 수 있다.
- **디스크 문서 목록 조회**: 프로젝트 작업 폴더에서 마크다운 문서를 찾아 목록으로 반환한다.
- **디스크 문서 내용 조회**: 목록에서 고른 문서 하나의 본문을 반환한다.

데이터베이스 지식과 디스크 문서는 서로 다른 출처다. 전자는 Clawket이 작업 흐름 속에서 쌓은 내부 지식이고, 후자는 사람이 레포에 직접 써 둔 일반 문서다. 위키 화면은 이 둘을 한 화면에 모아 보여준다.

## 요청 / 응답
**지식 트리 조회** — 요청 시 "어느 항목을 루트로 삼을지", "어느 플랜으로 범위를 좁힐지"를 선택적으로 줄 수 있고, 둘 다 없으면 전체를 받는다. 응답은 지식 항목들의 계층 목록이다.

**디스크 문서 목록 조회** — 요청에는 어떤 작업 폴더를 뒤질지(작업 디렉터리 경로)와, 위키 경로 설정을 가져올 대상 프로젝트를 함께 보낸다. 응답은 문서 목록이며, 각 항목은 폴더 기준 상대 경로, 확장자를 뗀 이름, 문서 안 첫 번째 큰 제목(없으면 파일 이름), 파일 크기, 마지막 수정 시각, 그리고 그 문서가 어느 위키 루트(예: docs 폴더, 혹은 작업 폴더 최상위)에서 왔는지를 담는다.

**디스크 문서 내용 조회** — 요청에는 작업 폴더 경로, 읽고 싶은 문서의 상대 경로, 대상 프로젝트를 보낸다. 응답은 그 문서의 경로·이름·본문 전체·형식(마크다운)·크기·수정 시각이다.

## 권한 / 제약
- **읽기 전용**: 세 조회 모두 어떤 상태도 바꾸지 않는다.
- **위키 경로 설정 기반 탐색 범위**: 디스크 문서를 읽을 때, 대상 프로젝트에 위키 경로가 설정돼 있으면 그 폴더들을, 없으면 기본값(docs 폴더)을 뒤진다. 추가로 작업 폴더 최상위의 마크다운 문서(README, CHANGELOG 같은 것)도 함께 목록에 포함한다.
- **탐색 깊이·크기 한계**: 폴더를 너무 깊이 파고들지 않도록 하위 단계 수에 상한이 있고, 일정 크기 이상으로 큰 문서는 목록에서 제외한다. 숨김 폴더(점으로 시작)와 의존성 폴더(node_modules)는 건너뛴다. 마크다운(.md/.mdx)만 대상이다.
- **경로 이탈 차단(보안 제약)**: 문서 내용 조회는 요청된 경로가 허용된 위키 루트(작업 폴더와 설정된 위키 폴더들) 안에 실제로 들어 있는지 정규화된 절대 경로로 다시 확인한다. 범위를 벗어난 경로를 요구하면 거부한다. 이는 위키 화면을 통해 임의의 시스템 파일을 읽어 가는 것을 막기 위한 안전장치다.
- **빈 결과는 정상**: 작업 폴더 경로가 비어 있거나 존재하지 않으면 오류 대신 빈 목록을 돌려준다. 화면은 이를 "문서 없음" 안내로 표시한다. 내용 조회에서 경로가 누락되면 잘못된 요청으로, 파일이 없으면 없음으로, 허용 범위 밖이면 금지로 구분해 응답한다.

## provenance
디스크 위키(목록/내용) 라우터는 `daemon/src/routes/wiki.rs`에 있으며, `/wiki/files`(목록)과 `/wiki/file`(내용)을 제공한다. 지식 트리(`/wiki/tree`)는 별도 지식 라우트에서 제공되며 클라이언트 호출부는 `desktop/apps/desktop/src/data/api.ts`의 위키 관련 메서드에서 확인된다. 제공 주체는 데몬(component.daemon)이고, 호출 주체는 웹/데스크탑 위키 화면이다. 데이터베이스 지식과 디스크 문서가 별개 출처라는 점이 이 조회의 핵심 의미이므로, 재구현 시에도 두 출처를 분리해 한 화면에 합치는 구조를 유지해야 한다.
