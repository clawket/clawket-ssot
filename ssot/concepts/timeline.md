## 정의

타임라인은 "이 프로젝트에서 시간순으로 무슨 일이 있었나"를 한 줄기로 보여주는 집계 뷰다. 프로젝트 안의 활동은 여러 곳에 흩어져 기록된다 — 상태가 바뀌었거나, 무언가 만들어졌거나 수정됐거나, 담당자가 배정됐거나, 코멘트가 달렸거나, 지식 항목이 생겼거나, 실행이 시작·종료됐거나, 질문이 올라왔거나. 타임라인은 이 흩어진 기록들을 하나의 시간순 목록으로 합쳐 최신 것부터 보여준다.

각 항목은 무슨 종류의 이벤트인지, 어떤 대상(태스크 등)에 대한 것인지, 그 대상의 제목, 누가(행위자), 언제, 그리고 종류별 세부(상태 변경이면 어떤 필드가 무엇에서 무엇으로 바뀌었는지, 코멘트면 본문, 지식이면 제목과 종류, 실행이면 담당 에이전트·소요 시간·결과 등)를 담는다. 보고 싶은 종류만 골라 거르거나, 페이지 단위로 끊어 볼 수 있다.

타임라인은 새로운 진실을 만들지 않는다 — 이미 다른 곳에 기록된 활동을 읽어 모아 보여줄 뿐인 파생 뷰다.

## 엔티티 (DB)

타임라인은 자체 저장 테이블이 없다. 여러 출처를 합쳐 그때그때 만들어내는 결과다. 상태 변경·생성·수정·담당자 배정 이벤트는 활동 기록에서, 코멘트는 코멘트 기록에서, 지식은 지식 항목에서, 실행 시작·종료는 실행 기록에서(종료 이벤트는 종료 시각이 있는 실행만, 그리고 소요 시간·결과를 함께), 질문은 질문 기록에서 끌어온다. 담당자 필드가 바뀐 변경은 일반 상태 변경이 아니라 "배정" 이벤트로 분류된다.

모든 출처는 프로젝트 단위로 걸러진다 — 대상이 태스크면 유닛·플랜을 거쳐 프로젝트에 닿는 경로로, 지식·질문처럼 유닛이나 플랜에 직접 붙을 수 있는 것은 그 경로로 프로젝트를 확인한다. 합쳐진 결과는 발생 시각 기준 최신순으로 정렬되고, 요청한 개수·시작 위치만큼 잘라 돌려준다(기본 100건).

## API 표면

- 한 프로젝트의 타임라인을 조회한다. 개수(기본 100)·시작 위치·이벤트 종류 필터(쉼표로 여러 종류)를 줄 수 있다. 종류를 하나도 매칭하지 않으면 빈 목록을 돌려준다.

조회는 읽기 전용이다 — 타임라인을 통해 무언가를 바꾸지 않는다.

## 불변식

- 타임라인은 파생·읽기 전용 집계다 — 자체 상태를 쓰지 않으며 출처 기록을 바꾸지 않는다.
- 모든 이벤트는 한 프로젝트 범위 안에서만 모인다(프로젝트가 집계 경계).
- 합쳐진 이벤트는 발생 시각 기준 최신순으로 정렬된다.
- 실행 종료 이벤트는 종료 시각이 기록된 실행에 대해서만 만들어진다.
- 담당자 변경은 일반 상태 변경과 구분해 "배정" 이벤트로 표시된다.

## 구현 위치 (provenance)

여러 출처(활동·코멘트·지식·실행·질문)를 합쳐 시간순으로 정렬하고 종류별 필터·페이징을 적용하는 집계 로직은 `daemon/src/repo/timeline.rs`, 프로젝트별 타임라인을 여는 HTTP 표면은 `daemon/src/routes/timeline.rs` 에 있다.
