## 정의

Active Project(활성 프로젝트)는 데스크탑/웹 대시보드가 한 시점에 "지금 보고 있는" 단 하나의 프로젝트다. 사용자는 여러 프로젝트를 등록해 둘 수 있지만, 화면은 언제나 그중 하나만 활성으로 두고, 그 프로젝트에 속한 작업만 보여준다. 대시보드의 모든 데이터 조회 — 플랜·유닛·사이클·태스크·지식 항목·타임라인·실행 기록 — 가 이 활성 프로젝트를 기준으로 한정(스코프)된다. 따라서 활성 프로젝트를 바꾸는 것은 곧 화면 전체의 작업 맥락을 통째로 갈아끼우는 것이다.

활성 프로젝트 선택은 브라우저 로컬 저장소에 보존된다. 그래서 앱을 닫았다 다시 열어도 직전에 보던 프로젝트로 자연스럽게 복귀한다. 처음 켜질 때나 저장된 선택이 더는 유효하지 않을 때(해당 프로젝트가 사라졌거나) 셸은 합리적인 기본값을 고른다 — 보존된 선택이 여전히 존재하면 그것을, 없으면 호출 측이 지정한 기본 프로젝트를, 그것도 없으면 활성화(enabled)된 첫 프로젝트를, 그마저 없으면 목록의 첫 프로젝트를 활성으로 삼고, 등록된 프로젝트가 하나도 없으면 활성 프로젝트는 비어 있다.

활성 프로젝트가 다른 값으로 바뀌면 두 가지가 따라온다. 첫째, 그 프로젝트로 스코프된 데이터 전체를 데몬에서 다시 가져온다. 둘째, 이전 활성 프로젝트에 속해 있던 현재 선택(`concept.selection`)은 새 프로젝트 화면에 어울리지 않으므로 자동으로 비워진다.

## 엔티티 (DB)

활성 프로젝트가 무엇인지는 데이터베이스의 비즈니스 엔티티가 아니라 화면 클라이언트가 들고 있는 상태다. "어떤 프로젝트가 활성인지"라는 선택 값은 브라우저 로컬 저장소(키: clawket.activeProjectId)에 문자열 식별자로 보존되어 재실행 시 복원에 쓰인다. 활성 대상이 되는 프로젝트 자체의 영구 데이터는 데몬이 소유하는 프로젝트 엔티티(`concept.project`)에 있다.

## API 표면

활성 프로젝트가 정해지면 셸은 그 프로젝트에 묶인 데이터 목록(플랜·유닛·사이클·태스크·지식·타임라인·실행 기록·위키 파일)을 데몬에서 병렬로 가져온다. 이후 데몬의 실시간 이벤트 스트림(`endpoint.daemon-events`)을 구독해, 해당 엔티티가 바뀌면 활성 프로젝트 범위에 맞춰 관련 목록만 다시 조회한다(삭제 이벤트는 네트워크 없이 로컬에서 즉시 제거). 활성 프로젝트를 바꾸는 행위 자체는 클라이언트 상태 전환이며, 그에 뒤따르는 재조회가 데몬 API를 사용한다.

## 불변식

- 한 시점에 활성 프로젝트는 최대 하나다(등록된 프로젝트가 없으면 비어 있을 수 있다).
- 대시보드의 모든 데이터 조회는 활성 프로젝트로 스코프된다 — 다른 프로젝트의 작업이 섞여 보이지 않는다.
- 보존된 활성 프로젝트 선택이 더는 유효하지 않으면(프로젝트가 사라짐) 셸은 정해진 우선순위로 대체 프로젝트를 고른다.
- 활성 프로젝트가 다른 값으로 바뀌면 종속 상태인 현재 선택은 반드시 비워진다.

## 구현 위치 (provenance)

활성 프로젝트의 결정·보존·복원, 전환 시 데이터 재조회, 그리고 실시간 이벤트에 맞춘 스코프 재조회 로직은 데스크탑 셸의 데이터 제공자(DataProvider)에 있다. 보존은 브라우저 로컬 저장소의 clawket.activeProjectId 키를 사용한다.
