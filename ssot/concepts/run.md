## 정의

실행 기록(Run)은 "이 태스크를 한 번 돌렸다"는 사건을 남기는 기록이다. 한 태스크는 여러 번 실행될 수 있고(재시도, 서브에이전트 분담 등), 그때마다 실행 기록이 한 건씩 쌓인다.

한 건의 실행 기록이 답하는 것은 다음과 같다.

- **어느 태스크의 실행인가**: 반드시 하나의 태스크에 속한다.
- **누가(어떤 에이전트가) 돌렸나(agent)**: 메인 에이전트인지, 어떤 종류의 서브에이전트인지, 어떤 스킬인지. 따로 지정하지 않으면 메인으로 기록한다.
- **어느 세션에서 일어났나(session_id)**: Claude Code 훅이 넘겨주는 세션 식별자(선택).
- **언제 시작·종료했나**: 시작 시각은 생성 시 찍히고, 종료 시각은 마무리할 때 찍힌다.
- **결과는 무엇이었나(result)**: 성공/실패/중단 등 자유 텍스트 결과와 메모.
- **상태(status)**: 대기(pending) → 시작됨(started) → 마침(finished), 또는 중단(aborted).

실행 기록은 보통 사람이 손으로 만들지 않는다. 태스크가 실행에 들어갈 때 훅이 자동으로 한 건을 생성하고, 실행이 끝나면 결과·메모와 함께 마무리한다.

"대기(pending)" 상태가 따로 있는 이유는 실행 준비와 실제 LLM 호출 시작을 분리하기 위해서다. 봉투를 얼려 프롬프트를 만들어 건네주는 단계에서는 아직 태스크를 "실행 중"으로 잡지 않고 대기로 두었다가, 실제 LLM 호출이 시작되는 순간 시작됨으로 넘긴다. 즉 "봉투를 얼리는 시점"과 "실행 시계가 도는 시점"을 떼어 놓는다.

### 봉투 스냅샷 — 왜 얼리나

실행 기록의 핵심 특성은 **시작 시점의 실행 봉투를 통째로 얼려 함께 보관**한다는 점이다. 태스크에 서명된 실행 봉투는 추가 전용(append-only)이라 이후에 새 서명이 옛 것을 덮어쓸 수 있다(부모가 다시 서명, 분해 정책 수정 등). 만약 실행 기록이 "봉투를 가리키는 참조"만 들고 있다면, 나중에 봉투가 바뀌었을 때 "그때 실제로 에이전트에게 뭘 보냈는지"를 더 이상 알 수 없게 된다. 그래서 실행을 받아들이는 순간 해결된 봉투를 JSON 한 덩어리로 얼려 보관한다(재현 가능성). 동시에 봉투를 가리키는 참조도 따로 들고 있어, 조인이 필요한 경우엔 그쪽을 쓴다 — 참조는 연결용, 얼린 스냅샷은 재현용이다.

## 엔티티 (DB)

실행 기록은 runs 테이블에 한 건씩 저장된다. 한 행이 담는 정보:

- 기록 식별자(접두사 RUN이 붙은 시간정렬 식별자).
- 소속 태스크(태스크가 삭제되면 그 실행 기록들도 함께 사라진다 — 종속 삭제).
- 세션 식별자(선택), 에이전트 표기(예: 메인 / 서브에이전트 종류 / 스킬 이름).
- 시작 시각(필수), 종료 시각(마무리 전엔 비어 있음).
- 결과(성공/실패/중단 등)와 메모(둘 다 마무리 전엔 비어 있음).
- 상태: 대기(pending) / 시작됨(started) / 마침(finished) / 중단(aborted) 네 값만 허용되며 DB 제약(CHECK)으로 강제된다. 기본값은 시작됨.
- 얼린 봉투 스냅샷(JSON 텍스트, 선택): 태스크에 활성 봉투가 없으면 비어 있다.
- 봉투 참조(envelope_id, 선택): 실행 생성 시점의 활성 봉투를 가리키는 연결용 값.

태스크별·세션별·상태별로 조회할 수 있도록 색인이 있다.

한 태스크에 **열려 있는(아직 끝나지 않은) 실행이 이미 있으면 새 실행을 만들 수 없다** — 이 경우 충돌(RUN_ALREADY_OPEN)로 거부하고, 기존 실행을 먼저 끝내라고 안내한다.

## API 표면

데몬 HTTP 표면에서 실행 기록을 다루는 경로:

- 목록 조회: 태스크·세션·프로젝트 기준으로 걸러 시작 시각 내림차순(최신 먼저)으로 반환한다.
- 생성: 태스크를 지정해 실행 기록을 연다. 상태는 대기 또는 시작됨만 허용(그 외엔 잘못된 요청). 봉투 스냅샷을 직접 넘기지 않으면 데몬이 그 시점의 활성 봉투 사슬을 해결해 얼린다. 이미 열린 실행이 있으면 충돌로 거부.
- 단건 조회.
- 시작 전환: 대기 상태인 실행을 시작됨으로 넘긴다.
- 마무리: 결과와 메모를 적고 종료 시각을 찍어 마침 상태로 만든다.

생성·시작·마무리 시 데몬은 실시간 이벤트(run:created / run:updated)를 내보내, 웹 대시보드와 watch 구독자가 즉시 반영할 수 있게 한다. 이 실행 이벤트들은 리플레이의 재생 대상이 된다.

CLI에서는 clawket run의 start/finish/view/list 하위 동작으로 같은 일을 한다(보통 훅이 자동으로 호출).

## 불변식

- **태스크 종속**: 모든 실행 기록은 정확히 하나의 태스크에 속하며, 태스크가 삭제되면 함께 삭제된다.
- **상태 폐집합**: 상태는 대기/시작됨/마침/중단 네 값만 허용(DB CHECK). 생성 시엔 대기 또는 시작됨만 받는다.
- **단일 열린 실행**: 한 태스크에 끝나지 않은 실행이 둘 이상 동시에 열려 있을 수 없다(생성 시 충돌 거부).
- **봉투 재현성**: 실행 시작 시점의 봉투를 얼려 보관하므로, 이후 봉투가 바뀌어도 그 실행에 무엇이 쓰였는지는 변하지 않는다.
