## 무엇인가

데스크탑 앱은 Clawket을 네이티브 창에서 사용하기 위한 설치형 애플리케이션이다. 바깥 껍데기는 Tauri(2 세대)로 만든 가벼운 셸이고, 그 창 안에 표시되는 화면은 웹 대시보드와 동일한 React(19 세대) 화면이다. 즉 화면 자체는 웹과 같은 것을 재사용하고, 데스크탑 앱은 "창 + 시스템 통합 + 데몬 기동" 역할을 더한다.

가장 두드러진 특징은, 앱을 실행하면 셸이 작업 데이터의 공급원인 로컬 데몬(clawketd)을 자식 프로세스로 직접 띄운다는 점이다. 사용자가 데몬을 따로 켤 필요가 없다.

## 누구를 위한 것인가

사람 운영자(persona.human-operator)를 위한 것이다. 운영자는 LLM 에이전트와 동일한 작업 상태를 보면서 칸반 보드·백로그·타임라인·위키·요약을 검토·관리하는데, 데스크탑 앱은 이를 브라우저 탭이나 터미널 명령 없이 독립 창 하나로 제공한다. 앱을 켜는 것만으로 데몬 기동과 연결까지 한 번에 처리되는 점이 이 페르소나에게 주는 핵심 편익이다.

## 서비스 영역

데스크탑 앱이 제공하는 화면 영역은 웹 대시보드와 동일한 다섯 갈래다 — 요약(Summary), 보드(Board), 백로그(Backlog), 타임라인(Timeline), 위키(Wiki). 화면 코드는 공유 UI 패키지와 웹 대시보드 자산을 그대로 재사용하므로, 데스크탑 앱 고유의 책임은 화면 그 자체보다는 다음 세 가지다.

- **창·시스템 셸**: Tauri 셸이 OS 창, 커스텀 프로토콜, 시스템 통합을 담당한다.
- **데몬 동반 기동**: 앱이 시작될 때 로컬 데몬을 자식 프로세스로 띄운다. 데몬을 찾는 순서는 환경변수 지정 → 앱 바이너리 옆/플러그인 설치 경로 후보 → PATH 탐색이다. 이미 데몬이 떠 있으면 데몬 자신의 잠금이 중복 실행을 거부하므로, 앱은 그 상황을 허용하고 대신 헬스 핑으로 생존을 확인한다.
- **연결 확인**: 데몬이 자리잡을 시간을 잠시 둔 뒤 유닉스 소켓으로 헬스 핑을 보내 연결을 검증하고, 메인 스레드는 그 사이에도 창을 계속 그린다.

## 접근 매트릭스 (역할 → 서비스)

데스크탑 앱은 단일 페르소나(사람 운영자) 전용이며, 별도 역할 구분이나 권한 분리가 없다. 운영자는 다섯 화면 영역 전부에 접근한다. 에이전트 측(LLM 코딩 에이전트)은 데스크탑 앱이 아니라 플러그인·CLI·MCP 경로로 동일한 로컬 상태에 접근하므로, 둘은 같은 데이터를 보되 진입 표면이 다르다.

## 기술 스택 (제품 맥락)

- **셸**: Tauri 2 (Rust 기반). 창·시스템 통합과 데몬 자식 프로세스 기동을 담당하며, 셸 자체는 데몬을 직접 띄우고 소켓으로 헬스 핑만 보낼 뿐 작업 데이터 로직은 갖지 않는다.
- **렌더러(화면)**: React 19. 웹 대시보드와 공유하는 화면 코드.
- **공유 디자인 시스템**: 모노레포의 공유 UI 패키지(@clawket/ui)에서 컴포넌트·디자인 토큰을 받아 쓴다.
- **데이터 공급원**: 로컬 데몬(clawketd). 데스크탑 셸의 Rust 코드는 CLI 크레이트에 직접 의존하지 않도록 분리되어 있고, 공유하는 것은 데몬 바이너리 이름과 탐색 순서라는 약속뿐이다.
