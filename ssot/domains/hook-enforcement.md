## 목적

에이전트가 "무엇을 하고 있는지" 기록되지 않은 채로 코드를 고치는 것을 막는 것이 이 영역의 일이다. 활성 태스크가 없으면 변경 도구를 통째로 차단하고, 위험한 명령(작업 트리를 되돌리는 파괴적 git/쉘 명령)을 실행 전에 잡아내며, 검증 워크플로우의 규율(시나리오 추적·배치 크기·근거 필수·동기화와 추론의 분리)을 매 작업 시점에 강제한다. 결과적으로 "모든 행동은 추적되고, 모든 세션은 맥락을 가진다"는 약속이 자동으로 지켜진다.

## 경계와 핵심 개념

포함:
- 훅 이벤트별 게이트 — 세션 시작 시 데몬 보장·대시보드/규칙 주입·설치 게이트, 프롬프트 제출 시 활성 태스크 컨텍스트 주입과 경고, 도구 사용 전 차단 판정, 도구 사용 후 변경 기록, 서브에이전트 시작/종료 시 바인딩·요약·자동 완료.
- 활성 태스크 게이트 — 활성 태스크가 없으면 변경성 도구(서브에이전트 스폰·팀 생성·메시지 전송·편집·쓰기·쉘) 호출을 차단한다.
- 파괴적 명령 가드 — 정해진 위험 명령 카탈로그를 정규식으로 하드 블록한다.
- PDD 안티패턴 검사 — 시나리오 ID 누락, 배치 30 초과, 근거 NULL, 벌크 동기화 단계에 추론이 섞이는 패턴을 막는다.
- 티어 게이트 — 태스크 등급에 맞는 모델 사용을 검사하되 다운그레이드는 경고(advisory) 수준이다.

제외:
- 상태 변이를 DB에 영구 저장할지의 판단(데몬의 FK·단일 active·근거 필수 같은 제약) — 훅은 "이 도구 호출이 진행되어도 되는가"를, 데몬은 "이 변이가 영속되어도 되는가"를 본다. 두 계층은 상보적이며 중복하지 않는다.
- 의미 검색·임베딩(지식·RAG 영역), 수렴 판정 로직(PDD 검증 영역).

## 기능

이 영역의 게이트들은 사람·에이전트가 직접 호출하는 capability가 아니라, 다른 capability(태스크 라이프사이클 관리, 검증 라운드 실행 등)가 시도될 때 그 위에서 통과/차단을 결정하는 가드레일로 작동한다. 실현 주체는 Claude 어댑터(훅 진입점과 공유 핸들러)이며, 일부 영속 제약은 데몬이, 핸들러 무결성 보장은 설치 게이트가 떠받친다.

## 시스템 흐름

Claude Code가 훅 이벤트를 발생시키면 얇은 2줄 셰임이 공유 핸들러로 라우팅한다. 핸들러는 데몬에 읽기 전용 질의를 던져 현재 작업 상태를 확인하고, 게이트별 판정을 내린다. 예를 들어 도구 사용 전(PreToolUse)에는 활성 태스크 여부·파괴적 명령·PDD 안티패턴·티어를 검사하고, 도구 사용 후(PostToolUse)에는 파일 변경을 활성 태스크에 기록한다. 서브에이전트가 뜨면 배정 태스크에 묶고, 끝나면 결과 요약을 붙이고 근거가 갖춰졌으면 태스크를 자동 완료한다. 플랜 모드를 빠져나갈 때는 출력 형상을 strict 검증해 Clawket 플랜으로 등록되도록 유도한다.

게이트 결정과 상태 영속은 분리되어 있다. 핸들러는 "진행 가부"만 판단하고, 실제 상태 변이가 DB에 남을 수 있는지는 데몬의 제약(예: 완료 전환 시 근거 필수)이 따로 책임진다. 각 게이트가 정확히 한 곳에만 사는 단일 강제 지점 원칙 덕분에 두 계층이 같은 규칙을 두 번 검사하는 일이 없다.

## 다른 도메인과의 관계

- 작업 관리 영역에 의존한다(`depends-on`) — 게이트의 판정 기준 자체가 활성 태스크·active 플랜·active 사이클 상태다.
- PDD 검증 영역과 협력한다(`collaborates-with`) — 검증 루프가 요구하는 규율(시나리오 추적·배치 한도·근거·동기화 순수성)을 훅 시점에 강제해 준다.
